# 01_Contract_Spec v0.18 第十八轮三方复审处置表（→ v0.19）

裁决输入：Kimi **GO**（0 / 0 / 0 / 0）；Codex **NO-GO**（0 BLOCKER / 4 MAJOR / 1 MINOR）；Claude Code **NO-GO**（0 BLOCKER / 2 MAJOR / 4 MINOR / 1 NIT）。合计 12 条编号意见，归并为 8 个独立问题，**全部采纳**（4 处合并两家方案）。所有问题均不造成重复发布，集中在"故障计数能否准确归到肇事任务"这一处。

本轮的根本修正是把两家共同指出的前提写成规则：**计数只在退役时的绑定快照恰为一个任务时发生**。上一轮"有确定触发者就只计触发者""持有独占许可即视为独占"两条都没有保证这个前提。

contract_version 由 1.0.0.dev7 升至 **1.0.0.dev8**。

## MAJOR

| # | 问题 | 来源 | 处置与采用方案 | 理由 |
|---|------|------|---------------|------|
| Y1 | 隔离头拿到独占许可时，不要求实例上已在执行的任务先结束。"没有可执行成员时普通派发照常"保证了成员转为可执行时实例上几乎一定有在飞任务；按"持有许可"读会把别人的毒丸算到隔离头头上，按"只有隔离头"读则毒丸永不被计数 | CC C18-01、Codex C18-02（前半） | **合并**：通道增加 open / draining / exclusive 三态——选出隔离头后先暂缓一切新出向，等实例上其他执行绑定结束、在飞只探测有界停止后才放行隔离头（取 CC 的"先预约后排空"）；在飞只探测无法确认停止时以计划性回收更换实例，不把等待无限传给隔离头（取 Codex）。计数条件统一为"绑定快照恰为一个 task" | 只有真正单独执行，崩溃才能归到具体任务 |
| Y2 | 阶段期限到期只计触发者：毒丸让 broker 部分停滞而心跳还在时，同实例所有任务都停住，谁的期限先到就算谁；期限短的无辜任务两次就被耗尽，毒丸的定时器每次都被解除、永不计数 | CC C18-02 | **采用 CC**：期限到期时快照恰为触发者才计数；快照 ≥ 2 则都不计、全部进入通道（触发者排首），在通道里单独执行再到期时才计数 | 期限到期只说明没按时完成，不说明原因在它自己 |
| Y3 | 执行绑定没有结束条件：已完成任务的历史 receipt 仍满足绑定谓词，"任务全部完成后的失效归启动 / 健康域"因此落空，已转只探测的任务也被当成执行中嫌疑 | Codex C18-01、CC C18-04 | **合并**：绑定 = task 非终态、非只能人工处理、处于三个执行阶段之一，且最近一条已放行的 execute receipt 指向该实例；终结、转"无法确定"、转人工、被替代即结束，历史 receipt 不再构成绑定 | 两家给出的谓词一致 |
| Y4 | 未核销的隔离头崩溃后也被转为"等待旧持有者"，但未核销任务根本没有授权持有者，旧实例回收不了时它永远不能再试 | Codex C18-03 | **采用 Codex**：成员状态按授权实际状态决定——未核销且有效保持可执行，已核销转等待旧持有者，无法确定转只探测，耗尽或终结为诊断结束；与核销事务单胜 | 不放宽已核销任务的静默条件，只是不为未核销任务等一个不存在的条件 |
| Y5 | 编排为取得负向证据主动回收实例（retire_requested）、运维重启都没有归属域，只能被塞进任务域或启动 / 健康域——前者误计无辜任务，后者让 launcher 把计划内回收当故障；hello 前的启动失败没有 epoch，事件模型却要求必填 | Codex C18-04（MAJOR）、CC C18-05（MINOR） | **合并**：新增计划性回收域 controlled_reclaim（retire_requested、隔离排空换实例、经 launcher 登记的运维 drain / restart），不计任何计数；未登记的重启仍按故障归责（取 CC）；hello 前事件 epoch 可空（取 Codex）；首次判定 CAS 生成唯一事件，后续通知复用 | "恰归一个域"仍成立，只是不再强迫正常回收冒充故障 |

## MINOR / NIT

| # | 问题 | 来源 | 处置 |
|---|------|------|------|
| Y6 | 暂缓派发没有接上既有规则：期限从何时起算、重启后会被恢复规则重送、换实例后怎么改投、何时算绑定、任务关闭时怎么作废、与下一个隔离头谁先 | CC C18-03、Codex C18-02（后半） | 采用。放行为单事务 CAS（复核实例、授权、模式、静默与通道许可，换实例走替代协议，放行时才写阶段、起算期限、建立绑定）；§2.5 恢复规则排除暂缓项，改由持久化的通道唤醒驱动；关闭类事件使暂缓 execute 作废；隔离头离开后先放行暂缓项、再选下一个隔离头 |
| Y7 | broker 自身故障（内存泄漏、依赖库崩溃）只要有流量，每次崩溃都算到任务头上，会逐个耗尽无辜任务，launcher 也不停机——这是上一轮按绑定划界的代价 | CC C18-06 | 采用。跨任务熔断：连续多次（缺省 2）有计数的故障分别落在不同任务上、其间没有任何任务正常完成 → 判为 broker 健康故障，停止自动拉起并告警；毒丸只会让同一任务反复计数，不触发熔断 |
| Y8 | 授权过期关闭没有把暂缓项限定为未核销（已核销的恢复派发与只探测不能因排队超时被当作未发布关闭）；该原因不经核销返回，却放进了核销拒绝的枚举；"诊断结束且未耗尽即回到常规"自相矛盾；排序键混比两种时间 | Codex C18-05、CC C18-07 | 采用。过期关闭只针对实际未核销且未进入发布的任务，原因作为编排侧关闭原因、从核销拒绝枚举中移除；隔离模式保持至任务终结；排序改为未核销在前按过期时间、已核销在后按核销时间 |
