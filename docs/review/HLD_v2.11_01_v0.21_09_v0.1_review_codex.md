## B. HLD 定向核对与问题

### 本版四项核对

- **按命中片段分类**成立：受审阅且绑定策略版本的常量/注释不是 PHP 程序；若转为入口、模板或 PHP 输入则不在豁免内。PHP 后缀、shebang、包依赖、解释器等信号仍独立拒绝。不能把“识别为 Python 字符串”单独当作用途证明，无法确认时按现文拒绝。
- **镜像/主机文件 digest 豁免**可执行：比对已审阅的扫描器文件实际字节，仅免文本信号；未列 digest 或修改文件重新命中。没有将 docs、测试目录或整个安装前缀免扫。打包后的实际文件需要匹配发布策略中的 digest。
- **current_digest**主干闭合：输入是当前实际安装内容与重新解析的工具闭包，不是旧记录；同策略、独立主机、读失败、合法更新重验均明确。实现时须对清单覆盖的实际文件（包括产品前缀外的声明工具）取当前内容，不得用包版本字符串冒充内容摘要。规范化字段已登记 B-7，不另报 01 同步缺陷。
- **例外双处校验**成立：无批准表项就不放行；两处需完整条目一致，而非只看工具名。当前“无”排除了 E0 自行签发例外。批准版本与清单应作为受控发布输入；普通注册方不能自己改两处来取得许可。

### H211-01 — MINOR：声明加一次观测仍未规定如何处理未观测到的宿主侧工具调用

**位置**：HLD §11.2“调用按声明判定”（第 877 行），§11.3 新用例；直接关联 D23 的产品工具闭包。

**原文依据**：“E0 预检对这些工具执行**一次子进程观测**……观测结果……进入声明清单”；“**运行中调用了未声明的工具视为部署缺陷**”；无关预装包只报告、不判失败；部署后新增工具或依赖须先扫描。

**问题/反例**：产品工具的普通分支只调用已登记程序，某错误处理分支却调用主机预装的 `php`。该依赖没有写入包元数据，E0 单次样例没有走到此分支。预装 PHP 被当作无关包，current/approved 摘要也相等；后续 Run 进入该分支时，文档只将未声明调用定性为缺陷，没有定义执行前拦截或可执行环境闭包约束。调用口径可机械计算，但不能据一次观测断言运行中不会越出它。这是新增声明口径的局部落地缺口，不要求扫描整台主机或业务 buildroot。

## C. 01 问题

### C21-01 — MAJOR：“部分目标已出现”成为裁决硬守卫，却没有可持久化、可判定的报告字段

**位置**：01 §5.1 ReleaseReconcileReport / ReleaseProbeReport（第 627、631 行）、新增裁决事实约束（第 648 行）；CF-AUTH-20j；§2.2a④为直接冲突点。

**原文依据**：恢复臂规定“**多目标发布中部分目标已在远端出现 → 只能上报 indeterminate**”；ReleaseProbeReport 仅有 `task_id, probe, remote_refs=[], probe_seq`，ReleaseReconcileReport 同样只有三值 probe 与可空 remote_refs。新增规则要求“**已记录或本次结果表明部分目标已出现 → 不允许 confirm_not_released**”。

**问题/反例**：两种合法观测——①已确认目标 A 发布、B 无法确定；②A/B 均无法取得观测——都能编码为 `probe=indeterminate, remote_refs=[]`；没有要求记录已出现目标、正向事实位或 remote_refs 的强制语义。后续强制 probe 超时，两种历史在 Ledger 中无法区分。C-11 却要求第一种禁止负向裁决，第二种可凭远端证据及 Q 裁决。即使把 remote_refs 填为非空字符串，契约也未定义哪些字符串代表“已出现”，不能靠解析任意 URL、报告文案或本次运维选择的引用来补 guard。

全量 `confirmed_happened` 的历史优先级已修好；缺口是本版新加的**部分出现事实锁存**。拒绝所有 indeterminate 的负向裁决虽安全，却删除了文档承诺的未知人工出口；继续允许则不能执行新增硬约束。这不是要求完善毒丸归因。

**候选 diff（最小事实位方案）**：

```diff
--- docs/01_Contract_Spec_v0.21.md §5.1
 class ReleaseReconcileReport(BaseModel):
+    observed_any_happened: bool  # 必填；本次是否确证至少一个授权目标已发生
 class ReleaseProbeReport(BaseModel):
+    observed_any_happened: bool  # 同义；不能由 remote_refs 是否为空推断
+ # confirmed_happened 必为 true，confirmed_not_happened 必为 false；
+ # indeterminate 可为任一值。部分目标已确证出现必须为 true。
+ # 校验及持久化绑定本授权目标集合；remote_refs 保留取证引用，不作判定载体。
--- §2.5 AuthorizationRecord / §5.1 裁决事务
+    observed_any_happened: bool = False  # 远端正向事实锁存，不是执行许可
+ # 受理本授权的合法 reconcile/probe 报告时，同事务 OR 入该事实位；
+ # holder 更替、探测暂停、新一次 unknown/未发生报告及重启不得清零。
+ # 历史 confirmed_happened 仍按现有规则只允许 confirm_released；
+ # 未达到“全量已发生”但正向事实位为 true 时，禁止 confirm_not_released。
+ # 旧版 indeterminate 无该字段的记录不得默认为“从无正向事实”；迁移时
+ # 保留无法分类状态并要求补证，不据此批准负向裁决。
--- §6.5 CF-AUTH-20j
+ 对部分出现与完全未知分别编码、落账、重启，再让强制 probe 超时；
+ 前者负向裁决必拒，后者仅按既有远端证据与 Q 规则处理。
```

**副作用**：增加两个 wire 报告的必填字段与一个 Ledger 锁存值，应按 dev 版本规则升级并更新 producer/consumer fixture；不增加发布命令、执行许可或自动裁决。若实现更需要逐目标事实，可采用结构化目标观测替代事实位，但不能只加自由文本。未知历史记录的保守迁移可能暂时需要人工补证。

**配套测试/夹具**：CF-AUTH-17d/20j/q 同时覆盖 reconcile 与 probe 来源；部分→未知、部分→当前报告未发生、全量已发生→未知、从未见正向事实→未知；在报告事务前后、K3 暂停前后与裁决事务前后 kill。事实位不得随 epoch/seq 改写，三值 probe 与事实位不一致时拒绝；只探测 FakePublisher 写计数仍为零。AST/schema 断言新增字段及版本兼容策略。

### C21-02 — MINOR：K5 作废句无法唯一划分“暂时不许放行”与“派发已无效”

**位置**：01 §2.2d K4/K5（第 195、198–199 行）、CF-AUTH-20i/20o。

**原文依据**：K4 规定暂停期间新 execute 暂缓，唤醒为人工恢复或正常结案；K5 要扫描全部暂缓项，但新增句为“**放行复核不通过（守卫、模式、暂停条件或通道许可以外的任一条件不满足）时……作废**”，条件恢复后由相应发送点重新生成。

## D. 01 五条时间线与交叉走查

按可达状态对乘积空间分解：先选业务事实行，再取提交点、域/快照、上限及调度行。尚未核销却已执行发布、start_failure 带执行绑定等非法组合直接拒绝，不伪造一种恢复出口。以下唯一出口指下一合法协议处置，不把“等静默/等人工”误称为已完成业务终局。C21-01 的格当前仍欠可判定事实；C21-02 的格须消歧。

记 Q = 原 granted_epoch 实例 reclaimed 且其可信 cgroup 子树静默；U = indeterminate；M = manual_only；H/F = released/release_failed 的 ledger 终局；L = 未核销耗尽、撤销授权后 F。

### 业务事实 × 恢复结果

| 时间线 | 未耗尽时的唯一路径 | 到限或人工出口 |
|---|---|---|
| 正常 | intent→consume CAS→执行→有效 outcome→H/F；正常结案释放预约和唤醒 | 到限先提交则按真实 consumed 分流；完成先提交则不再恢复。 |
| 核销后发生前崩溃 | 等 Q→新实例 resumed→对账；全未发生且原子许可通过才 proceed，否则按既有规则 F；无法确定→U | 到限→M，不能因恢复阶段名 awaiting_consume 而当成未核销 L。 |
| 发生后崩溃 | Q 后对账全发生→H；部分发生→U，不能重发执行 | M 中已记录全发生只准确认 H；部分事实的编码/锁存欠缺见 C21-01。 |
| 无法确定 | U 仅 probe；全发生→H；全未发生且 Q→F；全未发生而非 Q→retire_requested 后新序号重探；未知保持 publishing | 只探测影响到限→M+auto_probe_suspended、作废 held 自动 probe；裁决仍尝试一次绑定运维请求的只读探测，失败才 unknown。 |
| 实例 live 而单 task 失联 | 当前 armed 代次期限 CAS→实例 retiring→双快照归责/计数→按授权状态恢复 | 三上限按 K3；跨任务 deadline 达阈值暂停未核销新 execute，已核销恢复/probe 不停。暂停扫描的分类见 C21-02。 |

### 提交点 × 崩溃 × 编排重启

| 点位或竞争 | 唯一出口/恢复依据 |
|---|---|
| spawn 记录前失败 / 后失败 / hello 前超时 | 无 task 绑定，start_health；spawn_attempt_id 幂等，hello 前 epoch=None。 |
| hello 与 intent 放行、退役判定并发 | 按实例状态事务串行化：退役先胜不放行；放行先胜，随后的事件快照必须包含该 execute/probe。 |
| held intent 提交前/后，发送前重启 | 前无新记录；后不走普通重送、不计时、不入快照，扫描 held 经 K5。不能凭重启绕过 dispatch_paused。 |
| 放行事务提交前/后 | 前保留 held；后 execute 写绑定/代次/期限，probe 仅进入只探测在飞；崩溃不重置期限。 |
| 发送后 ACK 前 / ACK 后 completed 前 | 同 epoch 同 request_id 重送，逻辑处理幂等；completed 只表示送达，不能当 task/探测已结束。 |
| completed 后、outcome/report 前实例失效 | 非终态 execute 进入执行快照；未收到对应 probe_seq 报告的 probe 进入只探测快照；历史已结束 receipt 不进入。 |
| 替代事务前/后与新 epoch 再次崩溃 | 同 token 唯一 intent；旧或唯一替代项，不出现双意图；execute 已核销须 Q，probe 无需 Q，模式和暂停重新复核。 |
| consume/resumed/proceed、阶段到期与完成 | 当前 owner/phase_generation CAS 单胜；旧定时器无效；失联判定先提交则迟到旧实例执行类结果拒绝。 |
| RetirementEvent/计数/K3/窗口事务前后 | 前重做判定，后复用首事件；快照、各计数、停止/作废、预约释放及唤醒不得部分提交或重复计数。 |
| 正常结案与 K4 窗口登记竞争 | Ledger 提交序决定本次窗口；ACK/consume/resumed、合成关闭、人工结案均不清窗口。重放已有终局不再清一次。 |
| 运维请求→probe intent→取证→裁决各提交点 | origin/operator_request_ref 来自已认证入向请求；同请求只一次逻辑 probe，重启复用结果；事实优先，决定 CAS 一次。不因重启自动获得第二次 operator_force。 |
| 预约释放与 outbox 消费前后 | selection_seq CAS、固定批次/进度持久化；旧 receipt.reservation_seq 不释放同 epoch/同 task 的新预约。 |

### 三域 × 两份快照

B=执行绑定快照，P=只探测在飞快照；影响集合是 B∪P。

| cause/快照 | 互斥域 | 结算与出口 |
|---|---|---|
| start_failure（hello 前） | start_health | 无 B/P，按 spawn 恰一次；不伪造 epoch。 |
| lapsed，B=P=∅ | start_health | launcher 连续失败上界；完成后的历史 receipt 不改变域。 |
| lapsed，B 非空、P 任意 | task | charged⊆B；B∪P affected 各一次；归因可零计数。 |
| lapsed，B 空、P 非空 | task | 无可被 K1 计数的 execute，P 仍计影响；不能同时计 launcher 失败。 |
| 有效 phase_deadline | task | 当前 armed owner 的触发者须在 B；空 B/旧代拒绝，不另选一个域。 |
| retire_requested，任意合法 B/P | controlled_reclaim | 自动回收计 B∪P affected；不计 loss/interrupt/start。非 Q 的负向事实仍不能映射 F。 |
| isolation_drain，B 空 | controlled_reclaim | P affected+1；P 空也不凭空计任务影响；B 非空直接拒绝该请求。 |
| 已登记运维 planned_restart | controlled_reclaim | 不扣自动预算；与未经登记的 lapsed 明确区分。 |
| 后续 lapsed/重复退役请求/launcher 重启 | 首事件原域 | 不换域、不重新取快照、不重复增加任何计数。 |

小型谓词枚举的 37 个合法组合均恰归一个域。原 U 只探测 ACK 后不报告、短周期新 probe 被 held、反复 isolation_drain 的循环，如今每次 P 中 U 都扣 affected；上限时自动 probe 作废，旧循环不能免费延续。等待旧 holder 不能静默是可见安全等待，不属于自动换实例次数的终止承诺。

### K3 三上限 × K4 停止 × K5 放行

| 条件 | 唯一要求/边界 |
|---|---|
| loss/interrupt/affected 都未到限 | 依事实/Q/模式恢复；不需要先准确识别肇事者。 |
| 任一到限，实际未核销 | L；撤销授权与关闭同事务，旧 consume 拒绝。 |
| 任一到限，实际已核销 | M，解除执行定时器；仅人工收尾，不再 execute。 |
| P 中任务影响耗尽 | M+暂停自动 probe；held 自动 probe 同事务作废，运维单次探测可取得 intent 名额。 |
| 同事件同时在 B/P 或同时达到多种上限 | 影响只+1、分流只一次；已提交事件重放不改变结果。 |
| lapsed、被计数或本事件达到 K3 上限 | 不同 task 入 K4 故障窗口；零归因但影响耗尽也登记。 |
| lapsed、多绑定且未计数未耗尽 | 不入故障窗口，但 affected 不漏；后续耗尽不能继续豁免。 |
| phase_deadline 达不同任务阈值 | dispatch_paused，而非 launcher 停机；新未核销 execute 暂缓；已核销恢复及 probe 继续。 |
| 暂停中授权过期 | 仅未核销且 running 者按 C-09②关闭，原因可见；已核销不受原 expires_at 关闭。 |
| 暂停中人工恢复/一次正常结案 | 清暂停并持久化唤醒合法 held；重启不能丢失该动作；C21-02 要明确临时等待保留。 |
| task 终结 / U或M / 自动 probe 暂停 | 分别作废两类 / 仅 execute / held 自动 probe，不能留下阻塞 token 的废弃项。 |
| 独占头终局/U/M/退役/未生效时失去准入 | 依对应 selection_seq 释放、同事务唤醒；正常阶段切换不释放。 |
| 新流量与 held 批次并发 | 固定待处理批次不被无限扩充；处理合法暂缓项后再选新预约。永久等 Q 的成员不得独占阻塞其他 Run。 |

### 人工裁决与自动路径边界

- 已记录全量 confirmed_happened，即使当前强制 probe 超时或报全未发生，也不能判 confirm_not_released；冲突需审计。
- 只有内部 RetirementEvent 引用不能满足 evidence_refs；`probe_report` 要由服务端校验本授权绑定，`external_record` 必须确为远端记录，不能仅以客户端标签把 internal_refs 改名混入。
- 暂停仅禁止自动 probe，不能把已取得结果改成 unknown。运维请求绑定的一次强制 probe 失败允许继续证据分支，不触发无限重探；计数超过自动上限是显式人工例外，不恢复自动执行权。
- M 下 probe 对任一 recovery_state 合法，但只记录证据；payload 无发布计划、broker 只构造只读客户端，不能通过 probe 取得写能力。
- 部分出现与完全未知需要不同的负向裁决资格，当前 wire 无法区分，故不能确认所有人工格已有唯一可执行出口（C21-01）。

**范围调整结论**：将肇事归因移至实现策略仍成立；本轮补上了自动计划回收影响预算。剩余 MAJOR 在必须保留的事实约束，而非要求恢复毒丸精确识别保证。契约可以不保证准确归因，但不能省掉决定人工负向裁决资格的事实载体。
