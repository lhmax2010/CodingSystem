## 第一部分：HLD v2.8（GO）

### A. 处置落实核验

- P1–P4 逐条落文：复核不一致与父版本 CAS 失败同一出口（`sys.error(candidate_recheck_failed)`、不改记 purpose）✓；改交撤销的镜像节点例外 + 被拒提交不登记 candidate + 改交用新 request_id ✓；terminal 兜底用例改为绕过加载器直接构造状态 ✓；D23 新增并同步 §11.1/§11.2/§9/附录 B ✓。
- **三处合并方案评估（01 侧 X1–X3）**：①全局隔离通道 + 统一调度入口校验独占许可——**成立**：只有真正单独执行才能把崩溃归到具体任务，独占许可以统一入口（含只探测派发）校验，无双轨；②判定事务内计数 + 成员调度状态防阻塞饥饿——**成立**：计数不等 reclaimed（隔离头随即让出通道），只从 ready 成员选头且等待者不占通道保原顺序，授权过期给出可见原因；③执行绑定划界（intent 提交即绑定、就绪前不得绑定、判定与绑定串行化、无绑定失效归启动/健康域）——**成立**：互斥且完备，无需再约束两种上限的大小关系，"任务全部完成后的失效归启动/健康域"堵住了永久免计的尾巴。
- **记录更正**：两处更正（v2.5 处置表实为 4 条、R4 场景不可达）与存档核对准确。

### B. 改动面逐项核验

1. **复核不一致出口**：并行产 patch 分支的反例（失败节点预校验 revert、完成前收益判定写回改计划为 accepted）有唯一结局：作废 + sys.error(candidate_recheck_failed) + 重试重新预校验；计划保持 accepted、series 不变、purpose 不改记——无"按撤销提交的段以修复名义回退已接受优化"的形态。例外条款保留镜像节点两个合法环境出口；被拒提交不登记 candidate（不挡后续改交）、改交新 request_id 的幂等行为明确（复用旧 id 返回首次拒绝）。与冻结 §4.2.4 完成事务模型一致。
2. **D23（不得引入 PHP）落地完整性**：范围覆盖全部交付与部署内容（框架、Agent、Approval、broker 与官方 adapter、Gateway 与登录助手、Web 视图、deploy 资产与镜像、测试夹具）及运行时依赖闭包；业务接入面（Agent 插件、受限 adapter、宿主侧解析规则）注册时声明运行时、PHP 拒绝注册。边界清楚：外部系统实现语言不在范围；测试板上的业务用例脚本不属交付物、但其宿主侧适配/解析代码受约束。门禁可执行：lockfile 依赖闭包 + 交付物与镜像清单 + 全仓库文件扫描 + 注册时检查 + conformance 断言。任务点名的漏网路径逐一有覆盖：Web 视图前端（§9 已注明 Python + 静态资源）、运维工具（登录助手在 D23 清单内）、deploy 镜像基础层（镜像清单扫描）、测试夹具（清单明示）。现文原本无任何 PHP 组件，本条为显式约束 + 检查，落地完整。

## 第二部分：01_Contract_Spec v0.18（GO）

### 上一轮处置核验

本方第十七轮零 issue GO，无待核条目；X1–X4 落文核验通过：全局隔离通道与统一调度入口 ✓；判定事务内计数 + ready/waiting_holder/probe_only/diagnostic_done 调度状态 ✓；执行绑定划界（intent 提交即绑定、就绪前不得绑定、判定与绑定串行化）✓；waiting_holder 进入时点更正与意见计数更正 ✓。

### 走查矩阵（五条时间线 × 崩溃点 × 期限到期 × 计数上限 × 毒丸 × 无辜同实例 × 隔离期新流量，每格恰一出口）

1. **正常**：不变。✓
2. **核销后发生前崩溃**：RetirementEvent 恰归一域；已核销待 reclaimed 后经统一入口重派。✓
3. **发生后崩溃**：对账 happened → released 映射。✓
4. **indeterminate**：锁存；周期只探测；转 indeterminate 的成员同事务进 probe_only 并让出通道。✓
5. **实例存活但 task 失联**：有确定触发者 → 只计触发者 loss，同实例其他 task 仅解除定时器不计 interrupt（上轮 X1 反例修复）。✓
6. **毒丸（核销前 / 执行中）**：核销前崩溃按 intent 绑定归任务域；执行中崩溃同；首次多嫌疑 → 全局通道不计数、串行隔离；单独执行时逐次计数，至多 1 + max_task_interrupts 次后识别。✓
7. **隔离期新流量**：新任务/他成员/hello 扫描续送一律写 intent 暂缓（held_for_isolation=true、不计时、不构成绑定），隔离头离开执行阶段后按序放行；无 ready 成员时通道不阻塞普通派发。✓

**专项检查**：隔离通道不死锁不饿死（等待旧持有者回收的成员转 waiting_holder 且保留顺序、不占通道；子树永久不空只卡自身；顺序与成员身份持久化、重启不丢）；暂缓 intent 在隔离结束后全部按序放行；毒丸有限次数内必被识别；无辜任务不被他人计数（interrupt_count 恒 0，CF-AUTH-20g/20h）；每次退役事件恰归一个域（RetirementEvent 持久化 cause/domain/trigger/绑定快照）；manual_only 后无自动执行路径（C-09/④/execute 派发排除，只探测只产证据）；启动/健康失败与任务计数以执行绑定为界不重复不遗漏（无绑定的失效——含任务全部完成后的失效——归启动/健康域）。
