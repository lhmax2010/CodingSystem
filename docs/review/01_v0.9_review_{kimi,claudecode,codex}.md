## 3. 任务 B 结果

1. **反对：C-09 四支尚未闭合。**  
   核销前崩溃可由 `running + 未核销 → granted` 唯一恢复。但核销后发布前崩溃及发布中崩溃只凭“同 task、绑定匹配”即返回 `resumed`，没有连接 HLD §8.3 要求的“先远端对账；不可判定保持 publishing”，也没有证明旧 publisher 已静默。两个不同 request_id 的同 task 并发 consume 会依次得到 `granted`、`resumed`，与 CF-AUTH-02“恰一成功”冲突。其他 task 分支又在 §2.2(a) 与 `ConsumeRejected` 注释间对 Run 是否关闭给出不同答案。

2. **反对：三件套的结构已齐，但仍非零歧义。**  
   CommandName 与注册表实证为 17/17 对齐，CommandResponse 的 `status` 也可判别；但 authorization_consume 的 D12 被注册成成功响应臂，HLD §8.3 和 CF-SM-06/CF-AUTH-04却要求 `E-CP-D12-MISMATCH`。此外，合法 task_complete 的 float metrics 无法进入 `JsonValue` payload，响应也缺少并发关联规则。

3. **明确表态：这是实质豁免，须走 HLD 勘误；不是合规的存储特化。**  
   HLD §8.5 无条件规定“命令幂等（request_id）”。窗口外旧 ID 被当作新请求时，旧 trace 批次可再次追加，同 ID 异载荷也不再返回 mismatch。`release_dispatch` 同样不等价于 receipt：授权记录未绑定该命令的 request_id/payload digest，既不能复用首响应，也不能拒绝同 ID、不同但等价 manifest 的 payload；并发重投还可能同时获得 `granted/resumed`。

4. **接受：ProbeReceipt 三态与能力矩阵闭合。**  
   worker 每次回报前崩溃会生成 `synthetic_worker_loss` 并逐次消耗；spawn 明确失败生成 `synthetic_spawn_failed`；编排在 spawn 前反复崩溃则重派同组且不递增。达到上限后 replay-safe 与非 replay-safe 分别进入 abandoned+重放、unknown+sys.error；全零保留 digest 会使迟到真实回报被拒绝并审计。

5. **接受，有一项 MINOR 测试勘误。**  
   endpoint 词法和 `inprocess:<provider_id>` 对 D12 的影响已可判定。CF-SER-10 专属跨重启新 attempt，CF-SER-11 专属同 attempt 缓存丢失，两者互斥且覆盖既定恢复模型。CF-SM-13 遗漏部分既有 canonical negative vector，见 R9-06。

B-3（明示表态项）：这是合规的存储特化，不是实质豁免，无须走勘误。 判定依据：HLD §8.5"命令幂等（request_id）"要求的是语义性质——同请求不产生重复效果、异载荷可检测。v0.9 在全部 17 条命令上保持 scoped request_id + payload digest 异载荷检测（v0.8 的"免 receipt"豁免被撤销），仅将 receipt 存储特化为 (task, attempt) 滚动窗口 K≥64；窗口外重放的两条命令各有语义级兜底使重复效果依然不可能——heartbeat 由 seq 单调守卫兜底、trace_append 由 (task, attempt, 首 seq) 天然键去重——损失的只是"复用首响应"的保真度，而这两条命令的响应均为无信息 Ack。存储深度是实现维度，语义性质完整保留。出向 release_dispatch 经授权记录状态机去重等价于且强于 receipt：dispatch 的唯一效果就是 consume，授权记录的 granted/resumed/rejected 三臂穷尽覆盖全部重放形态，且耐 broker 重启（broker 无 Ledger 写权限下唯一自洽方案），编排侧出向事务仍记 receipt——闭环。

B-4（ProbeReceipt 三态 × 两能力矩阵）：接受。 三条时间线：worker 每次回报前崩溃 → 每 spawn 消耗一次（synthetic_worker_loss）→ 有界耗尽 → 按能力矩阵分叉（∧replay_safe→abandoned+版本化重放 / ∧¬replay_safe→unknown+sys.error），终态唯一——v0.8"无条件 unknown"与 CF-EF-02 的矛盾修正成立；spawn 系统调用持续失败 → synthetic_spawn_failed 逐次消耗、有界——这正是 v0.8 两态划分的漏洞（持续 spawn 错误落入"未 spawn"无限重派），三态以"spawn 记录"三值判别修复；编排 spawn 前反复崩溃 → 未尝试重派不递增、无假耗尽。合成保留全零 digest 使迟到真实回报必被①臂的 digest 校验拒绝并审计。上限在三条线上均不可突破。

B-5（CF-SM-13 + CF-SER-10/11 分工）：接受。 边界 vectors 七组各违反恰一条词法规则且配相邻 positive，判定唯一；label/总长/端口域/path 字符域/inprocess 绑定的文法自足。编排重启定案（重启→worker EOF 自杀→新 attempt→旧 candidate discarded）与 HLD §5.1.2 心跳自杀、§4.1 恢复即重执行逐字一致；CF-SER-10（跨重启=新 attempt 路径）与改写后的 CF-SER-11（同 attempt 内非 Ledger 缓存清空→仅自 Ledger 重建）分工互斥完备，v0.8 版 CF-SER-11 与 discard 规则的自相矛盾正确消除，payload_ref 的持久化价值保留。
