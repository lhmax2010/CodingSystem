## C. 第二部分问题

### C19-01 — MAJOR：通道只规定隔离头退役后回到 open，正常终结或转只探测时没有释放迁移

**位置**：01 v0.19 §2.2d“通道状态”“暂缓 intent 的生命周期”（第 194–195 行）；CF-AUTH-20k。

**依据**：新状态机的显式释放为“**exclusive 下隔离头所在实例退役时……通道回到 open**”；暂缓项只由“**通道回到 open 时写入**”的持久化唤醒驱动。另规定“**只有 ready 成员占用通道**”。上一版的“隔离头离开执行可能阶段后按序放行”在本次重写中没有保留为新状态机迁移。

**反例**：隔离头 A 在 E 上正常发布并关闭，B 的 execute 和 U 的 probe 已 held。A 的绑定按新规则结束、成员为 diagnostic_done，E 心跳正常，既不发生退役，也没有下一次 hello。通道记录仍是 exclusive(A,E)，B/U 没有放行许可；重启只恢复同一持久化状态。若 A 对账转 indeterminate，也会从执行绑定退出，但缺少 open 迁移。选头后、尚在 draining 的未核销 A 恰好过期，同样需要撤销已经失效的选择。“只有 ready 占用”表达了不变量，却没有定义与终局/模式变更事务一致的释放动作，当前显式迁移不能保证出口。

**候选 diff**：

```diff
--- docs/01_Contract_Spec_v0.19.md §2.2d 通道状态
- exclusive 下隔离头所在实例退役时……通道回到 open：先……再……
+ 释放选择的触发点包括：隔离头业务终结、转 awaiting_probe、转 manual_only、
+ 所在实例退役；以及 draining 中所选头因关闭/授权失效等不再满足准入。
+ 在对应判定事务内按 (selection_seq, head_task_id, target_epoch) CAS：
+ 更新成员状态、清空头与目标 epoch、置 open，并同事务写持久化调度唤醒。
+ 正常阶段切换 awaiting_consume→outcome/reconcile 不释放选择。
+ 实例退役先按 cause 与绑定快照归责；controlled_reclaim 不得因头在
+ exclusive 而被强制改计任务故障。重新选择使用新的 selection_seq。
+ 消费唤醒时先处理当时已排队的合法 held 项（execute/probe 分型见下），
+ 再为下一个 ready 成员预约 draining；处理批次与进度持久化，新流量
+ 不可无限扩充本批。重复唤醒或旧 selection 的完成通知不得释放新隔离头。
```

**副作用**：不增加通道状态，只补完整的事件→状态迁移和调度唤醒。用已存在的 selection_seq 防止旧回调释放新头；正常完成也唤醒普通流量，不再依赖一次额外故障才能恢复服务。

**测试/夹具**：CF-AUTH-20k 增“头正常 H/F 终局且 epoch 不变”“头转 indeterminate”“头耗尽 M”“draining 中头过期”；各点已有 held execute/probe，断言选择释放且合法项最终发送。业务关闭、清头、outbox 消费各提交点 kill；旧 selection 通知晚到不得释放新头。计划性回收与阶段期限竞争仍只归一个域、只计一次。

### C19-02 — MAJOR：暂缓 probe 被要求通过 execute 守卫并进入 awaiting_consume，合法只探测无法放行

**位置**：01 v0.19 §2.2d 第 194–195 行；直接冲突于 C-09、恢复臂④、C-11a 和只探测通道；§2.5(a)/(b)、CF-AUTH-20o。

**依据**：暂缓对象明确包含“**execute 与 release_probe_dispatch**”，但放行统一复核“**授权与 recovery_mode 守卫（C-09 / ④）**”，随后“**建立绑定、写 owner_epoch 与新 phase_generation / awaiting_consume / 期限**”。④ 排除 indeterminate，C-09 排除 manual_only；只探测恰用于“**indeterminate……以及 recovery_mode = manual_only 的已核销者**”。

**反例**：U/M 的合法 probe 在隔离期间 held，通道已经回到 open。严格套用 C-09/④，U 不满足恢复臂、M 被明确拒绝，probe 永久留在 intent，且同 token 不能创建第二个 intent。如果实现者自行跳过 guard，却仍执行共用阶段写入，就把只探测改为 awaiting_consume、武装执行期限；这既违反 probe 不触发 retiring，也可能使 U 的历史 execute receipt 重新满足阶段式绑定谓词。不能靠“只读 adapter 不写发布”解决编排侧的放行和计时错误。

**候选 diff**：

```diff
--- docs/01_Contract_Spec_v0.19.md §2.2d 暂缓 intent 放行
- 复核……授权与 recovery_mode 守卫（C-09 / ④）……清 held、建立绑定、
- 写 owner_epoch 与新 phase_generation / awaiting_consume / 期限，再发送。
+ 共同检查当前 live epoch、task 非终态、通道许可、token 唯一 intent；
+ target_epoch 已变化先走替代协议，替代项仍须经过本放行入口。
+ 按 payload.kind 互斥分型：
+ execute：复核 C-09/④ 的执行派发条件及适用的 Q，排除 U/M；清 held、
+ 建立执行绑定，写 owner_epoch、新 phase_generation、awaiting_consume
+ 及期限，再发送；同一 intent 重送不刷新期限。
+ probe：复核 publishing、已核销且 (indeterminate 或 manual_only)，
+ 以及只探测载荷/只读能力；发送不要求 Q。清 held 后仍为 probe，不写
+ awaiting_consume、不建立执行绑定、不武装执行阶段定时器；保持原授权
+ recovery_state/recovery_mode，按 probe_seq 与 probe_interval 管理重试。

+ task 已关闭时，execute/probe 的 held 项均作废；U/M 只作废旧 execute，

--- CF-AUTH-20o
+ 放行按 execute/probe 分组，不能对 probe 断言进入 awaiting_consume。
```

**副作用**：共用传输协议与唯一 intent 不变，仅将已经独立的命令语义延伸到新放行事务。保持只探测不会获得发布许可，也避免为读取事实错误增加 Q 前置。

**测试/夹具**：held U probe、M×四种 recovery_state probe，分别测试同 epoch/换 epoch、Q 有/无、授权原 expires_at 已过、放行前后 kill。应送达只读 adapter，FakePublisher 写计数为 0，无执行绑定/执行期限；M 不自动结案。execute 对 U/M 仍拒绝；关闭与放行 CAS 单胜且不留下阻塞 token 的废弃 intent。

### C19-03 — MAJOR：跨任务熔断把 consume/resumed 的正常完成当作进展，可被持续的执行期健康故障绕过

**位置**：01 v0.19 §2.2d“跨任务熔断”（第 199 行）、launcher 上界、CF-AUTH-20i；01 v0.18 处置表 Y7。

**依据**：正文要求故障间“**没有任何 release task 正常完成一个执行可能阶段**”；执行阶段包括 awaiting_consume、awaiting_outcome、awaiting_reconcile。CF-AUTH-20i 却要求“**与载荷无关的崩溃在至多 max_distinct_task_faults 个 task 被计数后触发熔断停机**”。处置摘要写的是“**其间没有任何任务正常完成**”，不等于任何一个阶段完成。

**反例**：FakeBroker 每次成功处理 consume/resumed，随后在发布执行或对账处理前因与载荷无关的缺陷崩溃。每个实例仅绑定一个 task，Q 可获得。A 重复到 interrupt 上限后 M；再处理 B、C……。每两次有计数故障之间都正常完成了 awaiting_consume，熔断条件永远不成立。启动/健康域也不计这些有绑定的失效，于是任意多个无辜 task 逐个耗尽，直接违背新夹具的上界。

另外，两个不同的真实毒丸先后发生，也能满足“不同 task 的连续故障”。仅凭退役事件不能证明根因必为 broker 健康故障；安全地暂停是可接受代价，“毒丸不触发熔断”则只能在单个毒丸及其余环境健康的特定夹具下成立。

**候选 diff（保留本版熔断方案的最小语义修正）**：

```diff
--- docs/01_Contract_Spec_v0.19.md §2.2d 跨任务熔断

- 正常完成一个执行可能阶段 → 判定为 broker 健康故障……
- 毒丸只会让同一 task 反复计数，不触发熔断。
+ 在无正常发布任务结案的窗口内，持久化记录有计数 RetirementEvent 的
+ distinct task_id 集合；同一事件只登记一次，同 task 重复故障不增加集合
+ 大小、也不清除集合。达到 max_distinct_task_faults 即暂停自动拉起并告警。
+ 正常结案指有效 broker outcome/恢复对账结果完成 ledger 终局映射，
+ 不包括 consume/resumed、dispatch ACK、预算耗尽的合成关闭或人工结案。
+ 正常结案与故障登记按 Ledger 提交序更新窗口；重启保留窗口与熔断状态，
+ 只有正常结案或显式人工恢复能清零。
+ 此熔断是保守的服务健康/可用性保护，不证明任务无错或 broker 有错；
+ 多个不同毒丸也可能触发暂停。单个毒丸、其余环境健康时不触发跨任务熔断。
--- CF-AUTH-20i
+ 新增每次 consume/resumed 均成功、随后处理任意 task 都崩溃的 FakeBroker；
+ 中间阶段完成不重置窗口，至多配置数量的不同 task 被计数后停止自动拉起。
```

**副作用**：需要持久化少量窗口状态或从事件日志可靠重建；比按相邻事件匹配更保守，两个独立毒丸可能让服务暂停。牺牲部分自动可用性，换取不把无限队列逐个耗尽；不能再宣称仅凭该规则准确定位根因。若选择转实现期，最后一节给出另一种明确收缩承诺的方案。

**测试/夹具**：除上述确定性反例，加入“同 P 多次故障”“两个不同毒丸”“中间只有 ACK/consume/resumed”“中间正常完成发布”“窗口登记/清零/熔断提交前后重启”“多绑定事件不增加 distinct 集”“controlled_reclaim 不计入窗口”。复核窗口与单 task 上限并发，不得重复计数或自动恢复 M。

### C19-04 — MINOR：bound_task_ids 被误放到 IsolationChannel，RetirementEvent 无法表达自己的判定快照

## D. 五条时间线与交叉维度走查

采用等价类分解，避免把不可达组合写成“通过”。每个可达组合按“授权/远端事实→传输提交点→退役域与快照→上限→通道”依次取一格；以下各表是同一组合检查的分层，不是相互独立的通过清单。标注问题编号的格当前不能保证唯一或有界出口。

记号：Q = granted_epoch 对应实例 reclaimed 且可信 cgroup 子树静默；H/F = released/release_failed 的固定 ledger 映射；U = indeterminate 锁存；M = manual_only；L = 未核销达到上限的撤销授权并 release_failed(dispatch_loss_exhausted)。Q 不是 kill 已发送、租约失效、leader 死亡或目录消失。

### 五条业务时间线

| 时间线 | 低于上限时的唯一事实出口 | 达上限及本版交界 |
|---|---|---|
| 正常 | consume 一次→执行→有效 outcome→H/F | 作为隔离头正常终结后须释放通道，C19-01；不能只关闭 Run、留下 exclusive。 |
| 核销后发生前崩溃 | Q 后新 epoch resumed；not_happened 且原子许可通过才执行，不通过则 F；未知→U | 已核销只能 M，不得套用未核销 L；即使恢复派发 phase=awaiting_consume 也按真实 consumed 状态判断。 |
| 发生后崩溃 | Q 后对账全部发生→H；部分发生/无法判断→U | 耗尽进入 M，人工裁决必须服从强制 probe；不能把计数耗尽当作未发生。正常对账关闭仍需 C19-01。 |
| indeterminate | 不再 execute；只探测发生→H，未发生且 Q→F，未 Q→计划回收后新序号重探，未知保持 U | M 的任一 recovery_state 只记证据，终局经 C-11。held probe 的现文放行有 C19-02。 |
| 实例 live、单 task 失联 | 当前阶段/代次期限 CAS→retiring；快照单个计 loss，多绑定不计数并隔离；之后依授权实际状态重排 | 未核销到限 L，已核销到限 M；心跳不掩盖 task 失联。若是 broker 普遍半停滞/健康故障，跨任务止损受 C19-03 影响。 |

### 提交点、崩溃点与到期竞争

| 点位 | 未核销 execute | 已核销非 U/M 的 execute | U/M 的 probe |
|---|---|---|---|
| spawn 写入前/后，exec 或 hello 前失败 | 无绑定；start_health，epoch=None，spawn 恰一次 | 保留已有 publishing/Q 义务，不伪造实例 epoch | 同左，不产生执行许可 |
| hello 已完成、intent 尚未提交 | 无绑定故障进 start_health | 未取得 Q 不派执行 | 可只读派发，不要求 Q |
| held intent 提交后、放行前 | 无执行阶段期限/绑定；实际未核销到 expires_at 才关闭 | 不因原授权 expires_at 关闭，仍须 Q | 不因 expires_at 关闭，不能用 C-09 条件拒绝合法 probe，C19-02 |
| 放行事务前后 kill | 前仍 held；后一次绑定、新期限；重送不刷新 | 同左，加 Q 与非 U/M 条件 | 只应释放读取，不写执行阶段；现文 C19-02 |
| 正常 intent 提交后、发送前 | 已绑定；与退役按提交顺序单胜 | 已绑定，原授权仍已核销 | 无 execute 绑定 |
| broker 受理后 ACK 前、ACK 后 completed 前 | 同 epoch 同 id 重送/去重，不再次核销 | 不重复发许可；新 epoch 重新 resumed/对账 | 同 id 读取重放，不变为 execute |
| completed 后失效 | completed 仅 ACK；未完成执行仍绑定 | Q 后恢复；终结/U/M 的历史 receipt 不绑定 | 不受历史 execute receipt 污染；C19-02 的错误改 phase 会破坏此性质 |
| 换 epoch、替代事务前后、旧 ACK 晚到 | 旧 intent 或唯一新 intent；旧 ACK 只审计 | Q 后替代；旧 epoch receipt 不转移执行权 | 替代仍须 probe，held 状态仍受通道管理 |
| consume / resumed / proceed 与阶段期限竞争 | 完成先胜则旧代期限无效；到期先胜则旧连接拒绝 | 新阶段 generation 与旧期限 CAS 单胜；Q 等待不计执行期限 | 无执行类期限；周期探测重试不得制造 task loss |
| outcome/对账终局或 U 提交前后 | 事务前沿旧状态，事务后不重开终局 | 绑定结束与结果落账一致；选择释放须 C19-01 | M 观测不自动映射；U 自动映射仍受事实/Q 限制 |
| 首次退役/后续 lapsed/launcher 重启 | 同一 RetirementEvent 不重复归责或计数 | 同左；物理 reclaimed 不是第二次计数 | controlled 回收零计数；事件快照模型需 C19-04 |

不存在合法的“尚未核销但已在发布阶段”或“U/M 自动获得 execute 许可”组合；若收到此类载荷，应由既有 guard 拒绝，不能为了让矩阵每格有结果而补造执行分支。

### 三域、快照、毒丸、上限与 broker 健康

| 判定事件/快照 | 域及计数 | 低于上限 / 到上限的出口 |
|---|---|---|
| retire_requested / isolation_drain / 已登记 planned_restart | controlled_reclaim；所有故障计数不增 | 实际未核销可在新实例恢复，已核销等 Q；不因普通计划回收新建嫌疑。已有隔离身份不应被清掉。 |
| phase_deadline，快照恰一个 task | task；该 task loss+1 | 未耗尽依实际授权 ready/waiting_holder；到限 L/M。即使实例心跳健康也成立。 |
| lapsed，快照恰一个 task | task；该 task interrupt+1 | 同上；核销前 ACK 前毒丸也被覆盖，不以 ACK 作为绑定起点。 |
| phase_deadline/lapsed，快照至少两个 task | task；全部零增量，进入隔离 | 期限触发者本批排首；毒丸与无辜先分离，再单独诊断，不误计其他绑定者。 |
| start_failure；或 lapsed 且快照空 | start_health；按 spawn_attempt_id 一次 | 连续上界后停止自动拉起、告警；成功 hello 本身不立即清零，需稳定期。 |
| 同事件重复、旧代 timer、已退役实例后到通知 | 复用首事件/忽略旧代 | 不改域，不再加计数，不额外创建替换实例；需要 C19-04 保留事件原始快照。 |
| broker 载荷无关故障，但每次先 consume/resumed 成功 | 当前均落 task，单个计数 | 逐个 task L/M，跨任务熔断现文可永不成立，C19-03。 |
| 两个不同毒丸，无正常任务结案 | 都可能形成单绑定计数 | 会触发跨任务暂停，不能证明为 broker 健康根因；C19-03 明确其保守代价。 |

phase_deadline 的有效事务要求当前 armed 阶段和 live owner，故“有效 deadline 但执行绑定为空”不是应额外分配一个域的正常输入；已关闭/U/M、旧 generation、held 未放行的期限均应先拒绝。start_failure 只对应未就绪启动尝试，不能被用来覆盖一个已就绪且有绑定的执行故障。以上前置与首次事件 CAS 一起，使三个域在可达输入上互斥且完备。

核销前、执行中崩溃和心跳正常的半停滞，都已统一到“快照恰一才计数”；多绑定时无辜者不因别人的期限先到而扣预算。**这不等于准确识别根因**：单绑定任务仍可能遭遇 broker 自身故障。毒丸有限故障次数的结论还依赖健康的诊断环境、必要 Q 最终可得、调度可以前进；它不是任意基础设施故障下的墙钟完成保证。loss/interrupt 交替时应使用两个预算共同限制，不能只引用其中一个预算作为所有混合故障的次数上界。

### 通道、成员和新流量

| 状态/事件 | 应有唯一调度结果与本版判断 |
|---|---|
| open，无 ready | 普通 execute/probe 可派；waiting_holder 不占通道，旧 holder 永不静默只阻塞相关已核销任务。 |
| ready 出现→draining | 新任务、hello 扫描、续送全部暂缓；已在飞 execute 使用原阶段期限，不因新流量延长排空。正常阶段数有限，故固定实例上的执行排空有界。 |
| draining 中只探测不响应 | 有界取消；不能确认停止则 isolation_drain 换实例，零故障计数。不能伪造停止证明直接独占。 |
| draining 中实例退役 | 本次 selection 作废；先按真正 cause/快照归责，再在新 epoch 重选。跨实例故障可反复发生，不能宣称无条件墙钟上界。 |
| draining 中头关闭/过期 | 头不能再派；须清选择并唤醒其他成员，C19-01。不能让“原头不存在”永久阻止排空完成。 |
| exclusive + 新流量 | 新 execute/probe 均 held，无绑定/执行计时；当前实例仅承担头的执行。 |
| exclusive 头故障 | 单绑定时计相应预算；未核销 ready、已核销 waiting_holder、U probe_only、耗尽/终局 diagnostic_done；回 open 处理 held 后再选头。 |
| exclusive 头正常完成或转 U | 应与故障分支一样释放选择并唤醒，但不扣故障预算；现文缺该迁移，C19-01。 |
| open 放行 held | 事务复核 epoch、token、模式及适用 Q；execute 正确，probe 需 C19-02；不得以恢复扫描绕过 held 标记。 |
| 重启、放行中换实例、重复唤醒 | 已提交选择/批次不丢；换实例走替代协议；旧 selection 回调不释放新头，C19-01/02 的补充测试覆盖。 |

**安全底线检查**：未发现本版新增合法的重复发布或 M 自动执行路径。C-09/④/execute 仍排除 M，U 锁存；probe 独立载荷不带发布计划，broker 只构造只读 adapter；M 的 probe 结果只作证据。人工强制 probe 全部发生时不能裁成未发生，负向裁决仍须 Q。C19-02 指向放行不通或错误计时，不将其夸大为已获得自动发布权限。

## F. “毒丸识别转实现期”的独立回答（不计入缺陷）

**有条件可行，而且建议收缩契约中的根因识别承诺；不能只删除归责段而保留对它的强验收保证，也不能把恢复安全与基本活性一起移走。** 本轮三项 MAJOR 中，C19-03 的诊断/熔断策略适合用运行数据迭代；C19-01/02 是当前已规定调度协议的出口与命令语义错误，只要保留该协议就必须修。若改为更简单的“故障后暂停并显式交由运维恢复”，应整体替换通道、held、hello 扫描和相关夹具，不能让两套协议并存。

单绑定崩溃只是相关性，不是因果证明。完全相同的可观察序列可来自有问题的 task，也可来自 broker 库缺陷、资源耗尽或多个独立毒丸；按任意健康故障模型同时保证“有限次准确找出毒丸”和“无辜任务一定不进入人工处理”不现实。建议将这些绝对承诺改为限定故障模型下的实现验收与运行指标，保留可核查的安全性质。

契约层至少必须保留：

1. **发布权与事实边界**：一次核销、当前 epoch 与持有者、Q 的可信来源、恢复先对账后原子许可、U 锁存、M 永不自动 execute；人工裁决受强制 probe 和远端事实约束。不能靠阈值、健康分或模型预测解除这些 guard。
2. **持久化出向协议**：唯一 intent、幂等重送、换 epoch 替代、旧 ACK 处理；execute/probe 明确分型。若仍有 held，必须规定放行/作废事务、期限起点、崩溃唤醒和最终去向；若取消 held，须用另一个完整的持久化待派协议替换。
3. **恢复预算和停止出口**：故障事件幂等、计时与完成互斥、重启不重置预算、自动恢复有界或转为可见暂停。未核销可撤销并失败关闭；已核销事实未明只能保持 publishing、探测/人工处理，绝不伪造未发生。launcher 重启/健康预算也不能仅靠指数退避冒充上界。
4. **回收与执行互斥**：可信 cgroup 身份和静默证明，旧实例命令不可恢复执行权；计划性回收不被误当重复任务故障。即使不承诺定位毒丸，也应记录影响范围与原始事件，不能把归因猜测冒充事实。
5. **调度基本活性与可观测性**：不存在无唤醒的永久 held/锁；不可恢复的依赖转为明确的 waiting/paused/manual 状态并告警，不能静默饿死其他 Run。暂停原因、影响任务、重试/回收次数和恢复权限可审计，恢复动作幂等。
6. **最小验收矩阵**：保留五条发布时间线的逐提交点崩溃测试、M/U 的零写调用、人工事实约束和终局唯一性。把“精确识别毒丸所需次数、隔离排序、distinct-task 熔断阈值、误报率和吞吐”移到实现策略及性能/故障实验，不再作为公开契约中的无条件保证。

这会接受更多保守暂停和人工排障，放弃“每个正常任务都能自动恢复”的强承诺；收益是先把发布安全和可恢复性实现、验证，再依据故障数据决定隔离复杂度。需明确改写 A3、相关状态/模型及 CF-AUTH-20g/h/i/k/o 的预期，作为一次受控的范围收缩，而不是用“实现期再看”豁免当前未闭合的出向协议。
