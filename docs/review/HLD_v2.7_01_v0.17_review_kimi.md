### A. 处置落实核验

- S1–S6 逐条落文：purpose 判定拆为受理预校验 + 完成事务权威复核（§7A.4"判定的事务位置"）✓；撤销条残留短语已替换（"未决计划期间不接受修复段，撤销段即候选段的逆变更"——我上轮 K-01 关闭）✓；§11.3 两条不可构造旧用例已替换 ✓；terminal 兜底理由改写为纵深防御、违规归 Optimization task ✓；make_revert 与拒绝响应携带 plan_id/parent_tree ✓；suites: auto 一律按需要 A/B ✓；审批呈现去重、构建根结论限定样本 ✓。
- **两处合并方案评估（01 侧）**：①核销前毒丸"按派发绑定识别 + 按授权实际核销分流"——**成立**：以持久化派发记录与实例绑定（不看 ACK）是唯一崩溃安全识别法；按阶段名分流会把已核销任务的恢复派发误当未核销（恢复派发同样处于 awaiting_consume），按实际核销状态分流正确。②launcher"持久化拉起记录 + 连续启动失败上界 + 派发送达后不计入启动失败"——**成立**：拉起记录先于启动使 hello 前退出也可计数（原方案计不到）；送达后失效归任务计数使执行期毒丸先被任务计数识别、不触发全局停机，两处划分互不重叠。
- **"记录更正"一节**：两处更正与正文/实测核对准确（v2.5 处置表确为 R1–R4 四条；R4 原触发场景在规则③下确不可达）。

### B. 改动面逐项核验

1. **purpose 预校验/复核拆分**：与冻结 §4.2.4 一致（计划创建/迁移只在 series 推进的完成事务内原子发生）。不一致出口唯一：受理与完成之间状态变化 → 完成事务复核失败 → 候选作废 + 父版本 CAS 失败按既有 sys.error 规则；重放复用 receipt 不重复建计划/计轮；并行候选由单写者完成事务串行，后到者在复核时见到未决计划而被拒、重试后预校验即拒绝——收敛唯一。
2. **E-CANDIDATE-NOT-REVERT 后的改交撤销**：make_revert 确定性生成、同 task 内改交、只消耗一次环计数（被拒提交不路由）；不改交直接结束 → sys.invalid_result（不可重试，归违规）——关系明确。
3. **未决计划下非 opt_patch_ready 即违规 + no_gain_found 净变更核对**：与 campaign 正常终局不冲突——全部撤销后无未决计划，no_gain_found 合法且其"无净变更"核对此时成立（撤销回 snapshot）。
4. **suites: auto 一律按需要 A/B**：四份示例全部 local 后端（verified）照常加载；示例一/二/四的 auto 套件因此要求 comparison 能力，local 满足；absolute-only 豁免限定显式锁定套件，无误放无误拒。

### 走查矩阵（五条时间线 × 崩溃点 × 期限 × 计数上限 × 毒丸 × 同实例无辜任务，每格恰一出口）

1. **正常**：不变。✓
2. **核销后发生前崩溃**：已核销须待 reclaimed → 替代协议重派 → resumed → 对账 → proceed → 执行。✓
3. **发生后崩溃**：对账 happened → released 映射。✓
4. **indeterminate**：锁存；周期只探测；manual_only 下任一恢复状态可探测但只作证据。✓
5. **实例存活但 task 失联**：代次 CAS 一次 → 同实例全部定时器同事务解除 → retiring → 回收 → 新 epoch → 重派重新武装；触发者计 loss、连带者计 interrupt、同一退役事件至多计一次。✓
6. **毒丸（核销前 / 执行中）× 无辜同实例**：首次崩溃嫌疑集 |S|≥2 → 不计数、串行隔离重派；隔离中 P 单独崩溃逐次计数，至多 1 + max_task_interrupts 次后识别（已核销 → manual_only；未核销 → dispatch_loss_exhausted 关闭）；B 至多受首次未隔离崩溃影响、不被连带计数、最终正常完成（CF-AUTH-20g/20h）。✓

**专项检查**：隔离重派不饿死不死锁（确定序、每任务有界崩溃上限、等待期不武装定时器、回收失败走告警而非无限等待）；毒丸有限次数内必被识别；无辜任务不进入只能人工处理（手动上限只及真正反复失败者）；manual_only 后无自动执行路径（C-09/④/execute 派发排除，C-11a 只产证据）；启动失败与任务计数不重复不遗漏（以派发送达为界）。人工裁决受强制 probe 约束，不能与远端事实相反。闭合。
