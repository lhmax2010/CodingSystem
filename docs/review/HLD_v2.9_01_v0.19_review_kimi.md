- 暂缓 intent：放行事务的六项复核齐全；重启不重送（§2.5 (a) 已排除 held 项）、通道唤醒驱动；关闭/manual_only/indeterminate 三类作废路径均写明。**成立**。

### 五条时间线 × 崩溃点走查（摘要）

1. **正常**：intent → consume → outcome → 两事务 receipt 协议；无新改动影响。
2. **核销后发生前崩溃**：retire_requested → controlled_reclaim（不计数、不入通道）→ 静默 → 持有者更替重派；已核销成员在通道内为 waiting_holder，静默后转 ready。恰一出口。
3. **发生后崩溃（indeterminate）**：锁存 + probe_only，不占通道；只探测为独立出向命令、不含 release_plan_ref，broker 侧只读 adapter 与 FakePublisher 写计数 0 的 conformance 约束仍在——**只探测通道不能被执行发布**，本版未改动该性质。
4. **实例存活但单个发布任务失联**：phase_deadline 到期 → 快照恰一个计 loss、≥2 进通道——半停滞毒丸场景下无辜短限期任务不再被耗尽（Y2 修复点）。
5. **新旧实例并存**：绑定建立与退役判定按同一实例状态串行化，判定先提交则禁止新绑定——无双重执行窗口。

### 重点问题逐项

- **排空能否被无限拖延**：不能。draining 起一切新出向暂缓（流量不能延长排空）；在飞 execute 受既有阶段期限约束（active 模式定时器武装，到期即退役并重排空——有界）；在飞只探测取消确认、无法确认时 isolation_drain 换实例——三路都有界。成员转 ready 与转 draining 在编排单写者事务序下无插队窗口；即使 open 态放行一笔普通派发，它带武装期限，仍然只让排空至多延后一个期限。
- **毒丸有限次内必被识别**：毒丸作为隔离头独占执行时快照恰为它本身，每次故障计数，至多 1 + max_task_interrupts（或 1 + max_task_losses）次后耗尽分流（manual_only / dispatch_loss_exhausted）。核销前毒丸由 awaiting_consume 期限 + 排空独占覆盖。**成立**。
- **无辜不被连带**：多绑定故障零计数；熔断只数"有计数且落在不同 task"的事件，多绑定事件与单毒丸重复计数均不触发熔断；broker 健康故障（每次崩溃恰好单绑定地杀死不同任务）在缺省 2 次内熔断停机——不存在能绕过熔断又不被计数的故障形态（≥2 绑定 → 零计数进通道 → 逐个隔离执行 → 若仍崩则变为单绑定计数 → 熔断）。**成立**。
- **manual_only 后无自动执行路径**：C-09 / 恢复臂④ / C-11a 守卫自 v0.17 起显式含 manual_only，本版未改动；绑定谓词排除 manual_only，通道对 manual_only 成员不占位。**成立**。

## "毒丸识别转实现期"问题（单独回答，不计入缺陷）

**结论：可行，且我支持在 freeze 后如此执行；但 v0.19 之后契约层已达到可以停手的收敛点，建议不再追加规则。**

理由：毒丸识别规则的本质是**可用性优化**（有限次内定位肇事任务、保护无辜任务），不是安全底线。安全底线——不重复发布（epoch + consume CAS + 静默合取 + DispatchReceipt 单 intent）、manual_only 后无自动执行、人工裁决受强制 probe 约束不违背远端事实——在 v0.13–v0.15 已闭合，且不依赖计数规则的正确性：计数错配的最坏后果是无辜任务被耗尽转入工或健康故障停机，全部是 fail-safe 方向。因此把识别策略（上界取值、熔断阈值、通道调度细节）留到实现期以运行数据迭代是安全的。

若转实现期，契约层至少必须保留：
1. **数据结构**：loss_count / interrupt_count 持久化、RetirementEvent（含 cause/domain/绑定快照）、recovery_mode 含 manual_only——否则实现期无法积累可迭代的运行数据，且审计无法重建归责；
2. **安全相关语义**：耗尽后的两种出口（未核销 release_failed / 已核销 manual_only）、manual_only 守卫、"计数与归责结论必须持久化且重启不丢"；
3. **上界存在性**：必须存在某个有限上界使毒丸必然转出自动路径——具体数值与识别路径（嫌疑集/通道/熔断的细节）可作为配置与实现策略迭代。

即：契约层管"必然终止于安全状态"，实现期管"多快、多准地终止"。v0.19 的现行文本已满足这一划分，我的 GO 不以转实现期为条件。

## 一句话总结

**HLD v2.9：可以 freeze**（D23 落地完整，余 1 MINOR 主机扫描口径 + 1 NIT 例外登记形态，可作勘误清单随 freeze 处理）；**01 v0.19：可以 freeze**（计数前提与隔离通道闭合，走查矩阵每格恰一出口，无新 issue）。
